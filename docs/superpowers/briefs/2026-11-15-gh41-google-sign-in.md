## Goal

A visitor to https://receipts-h745.onrender.com can sign in with Google and then start runs without the passcode under a per-user daily limit and see only their own runs in History, while a signed-out visitor keeps today's path (start a run with `DEMO_PASSCODE`, see the runs that belong to no user, read the demo card) under a global daily cap on signed-out runs; every rule is a pure function with a failing-first test, nothing reads a secret at import, and the spec, AGENTS.md section 9, ADR-0004, ADR-0005 and a new ADR-0008 record the change.

## Why it matters

The owner plans to post the app publicly on social media, and hackathon judges may open it while the Google OAuth app is still in Testing mode (only the owner can sign in). If sign-in were mandatory, judges and visitors could not start a run at all; if the passcode stays but nothing caps signed-out runs, a passcode that leaks on social media lets strangers burn the Anthropic and Keenable budget (the spec's anti-goal). Per-user History and limits are what make a public account worth having, and the records (spec non-goal "user accounts", the section 9 data rule "no accounts, no sign-ups") are currently false once this ships, so they change in the same PR or the repo lies about what it stores.

## Constraints

- **Rule Zero on counts.** Every limit message shows its denominator and window: `3 of 5 runs used today (UTC)`, never `limit reached`. Every number in the PR body carries its set (`N of M tests in tests/test_auth_routes.py`).
- **Typed boundaries (AGENTS.md section 3).** New domain types are frozen pydantic models or dataclasses in `src/receipts/auth/models.py` (new): `User` (id, google `sub`, `email`, `created_at`), `SessionUser` (user id, expiry), `IdTokenClaims` (`iss`, `aud`, `sub`, `email`, `exp`, `nonce`), `StartDecision` (allowed, or refused with a reason string that carries its count and denominator). No `dict[str, Any]` crosses a module line; the token endpoint's JSON is parsed into `IdTokenClaims` at the edge.
- **Business rules are pure.** Three pure functions, each with its own test file, no clock, no network, no database inside: `validate_claims(claims, *, client_id, nonce, now) -> IdTokenClaims` (issuer in `https://accounts.google.com` or `accounts.google.com`, `aud == client_id`, `exp > now`, `nonce` equal; raises `AuthError` naming which check failed), `may_start(user, passcode_ok, user_runs_today, signed_out_runs_today, per_user_limit, signed_out_cap) -> StartDecision`, and `callback_url(host) -> str` (returns exactly `http://localhost:8000/auth/callback` for `localhost`/`127.0.0.1` hosts and `https://<host>/auth/callback` otherwise; these are the two URIs registered on the Google OAuth app). I/O (token exchange, signature check against Google's keys, cookie signing, database counts) lives in injected edges.
- **Nothing reads a secret at import or in `create_app()`** (ADR-0005; `tests/test_settings.py::test_create_app_boots_with_an_empty_environment` and `.github/workflows/api-image.yml` both boot with an empty environment). Google and session settings are read per request through `get_settings()`.
- **Secrets by name only.** New names: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `SESSION_SECRET`, `RUNS_PER_USER_PER_DAY` (default 5), and the main session's addition `SIGNED_OUT_RUNS_PER_DAY` (default 20; not in the issue as written). Locally, `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` are in `~/.zshenv`; `SESSION_SECRET` is not (generate a throwaway value for local runs: `export SESSION_SECRET="$(openssl rand -hex 32)"`). No log line, error detail, test output or PR body ever prints a value, an ID token, a session cookie or a real email address.
- **Frozen files (AGENTS.md section 9, ADR-0006).** `src/receipts/contracts.py`, `src/receipts/fakes/**` and `tests/conftest.py` stay frozen: `RunService.start(request)`, `RunRepo.list_runs()` and `RunSummary` do not change. ADR-0008 (new) lifts the freeze **for issue #41 only** on three files, following ADR-0007's wording: `pyproject.toml` and `uv.lock` (one runtime dependency for OAuth/JOSE, `authlib` unless ADR-0008 justifies another; record the lock's package count before and after, and the `pip-audit` result), and `src/receipts/settings.py` (five optional fields on the existing lazy `Settings`: `google_client_id: str | None`, `google_client_secret: SecretStr | None`, `session_secret: SecretStr | None`, `runs_per_user_per_day: int = 5`, `signed_out_runs_per_day: int = 20`; the module docstring's list of names grows from five to ten).
- **Run-to-user link without touching the contracts** (main session's call on Q2): a `users` table (`UserRow` (new) in `src/receipts/db/schema.py`: id, `sub` UNIQUE NOT NULL, `email` NOT NULL, `created_at`) and a nullable `runs.user_id` column with a foreign key to `users.id`. `SqlRunRepo` (`src/receipts/db/repo.py`) grows `claim_run(run_id, user_id)`, `list_runs_for(user_id: str | None)` (None lists runs with no user) and `count_runs_since(user_id: str | None, since)`; `SqlUserRepo` (new, `src/receipts/db/users.py`) has `get_or_create(sub, email, now) -> User`. A signed-out passcode run has `user_id` NULL. The link is written right after `InProcessRunService.start` returns (`src/receipts/harness/service.py:72-78` creates the row before returning), so there is a sub-second window in which the run belongs to no user; accepted and documented.
- **Schema evidence against the real database** (AGENTS.md section 4): the `users.sub` UNIQUE and the `runs.user_id` foreign key are proven on Neon in `tests/test_db_constraints.py` by inserting the row each exists to stop, in the style already there (`_assert_rejected`). `create_schema` is `Base.metadata.create_all`, which adds the new table but does **not** add a column to the existing Neon `runs` table; ADR-0008 records how `user_id` gets onto the deployed table (an idempotent `ALTER TABLE runs ADD COLUMN IF NOT EXISTS user_id ...` run by `create_schema` or a one-off statement the owner runs, named in `docs/runbooks/render.md`), and the integration test proves the column exists on Neon by writing a row through `claim_run`.
- **Gradio and the UI lane.** `tests/test_ui_app.py::test_ui_module_reads_no_environment_and_no_settings` forbids `os.environ`, `getenv`, `get_settings` and `receipts.settings` in every `src/receipts/ui/*.py`, and every file there starts with `# pyright: basic` (ADR-0006). Identity reaches the UI only through an injected typed seam. **Do not use Gradio's `auth_dependency`**: in the locked gradio 6.32.0, a mount with `auth_dependency` answers 401 whenever the dependency returns `None`: on the page route (`gradio/routes.py:733-740`) and on `login_check` (`:448-459`), which guards `/config`, `/queue/join` and `/upload`. A FastAPI `TestClient` probe got 401 on `/ui/`, `/ui/config` and `/ui/gradio_api/login_check` with the dependency returning `None`, and 200 without the dependency. That would lock every signed-out visitor out of `/ui`, the opposite of option (b). Handlers that need identity take a `gr.Request` and hand its underlying Starlette request (`gr.Request.request`) to the injected seam.
- **One typed seam for the UI**: `Gate` (new Protocol, `src/receipts/auth/gate.py`) with `identify(request: starlette Request) -> SessionUser | None`, `start(request: RunRequest, passcode: str, user: SessionUser | None) -> RunId`, `history(user: SessionUser | None) -> list[RunSummary]` and `account(user: SessionUser | None) -> AccountStatus` (new model: signed-in email or none, runs used and limit for today). `src/receipts/api/wiring.py` builds the live `Gate` (it already owns `make_starter`, `LazyRunService`, `DemoRunService`); `create_app()` stores it on `app.state` before `mount_ui(app)`, the way it stores `run_starter` today (`src/receipts/api/app.py:62-65`); `mount_ui` passes it to `build_ui`. With no `Gate` on the app (`tests/test_ui_app.py::test_mount_ui_on_a_bare_app_falls_back_to_the_demo_service`), the UI behaves exactly as today.
- **Start rule (`may_start`), the owner's option (b):** a signed-in user needs no passcode and is allowed while `user_runs_today < runs_per_user_per_day`; a signed-out visitor is allowed only with a correct passcode (constant-time compare, as `check_passcode` in `src/receipts/api/routes.py:37-43` and `_check_passcode` in `wiring.py:278-284` do today) and while `signed_out_runs_today < signed_out_runs_per_day`; after either check, `require_keenable_key` as today (passcode or session first, so a stranger learns nothing about the key). Local demo mode (no live settings, no passcode configured) keeps today's passcode-free demo replay (`make_starter`, `wiring.py:296-302`); the demo replay writes nothing and is not counted.
- **Modes.** Sign-in needs `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `SESSION_SECRET` and `DATABASE_URL`; with any missing, `GET /auth/login` answers 503 naming the missing variable (never its value), like `check_keenable_key`, and the UI hides the sign-in link. Everything else (passcode runs, History of runs with no user, the demo card) works exactly as today whether or not Google is configured.
- **Cookies.** Session: `HttpOnly`, `Secure`, `SameSite=Lax`, `Path=/`, signed with `SESSION_SECRET` (HS256 compact token or equivalent from the one dependency), carrying our user id and an expiry (7 days), never the email or the Google token. The OAuth round trip (state, nonce, PKCE verifier) lives in a second signed, short-lived (10 minutes) cookie, so no server-side session table is needed. Logout is `POST /auth/logout` and clears the cookie.
- **Scopes and data minimisation.** Scopes `openid email` only. Store `sub` and `email`, nothing else from the profile (no name, no picture). `GET /api/runs/{run_id}` stays readable by anyone who has the id (the voice agent and the seed script depend on the read routes); only the **list** is scoped.
- **API passcode path unchanged** (main session's call on Q3): `POST /api/runs` with `X-Demo-Passcode` keeps working as today for `scripts/seed_demo_runs.py` and the runbook; it counts as a signed-out run against `SIGNED_OUT_RUNS_PER_DAY`. `GET /api/runs` returns the runs with no user unless the request carries a valid session cookie, in which case it returns that user's runs.
- **Gates stay gates.** `bin/jig` four rows `ok`; pyright strict on `src/` except `ui/` per file; no `# type: ignore`; `uv lock --check` 0; `uv run pip-audit --strict --vulnerability-service osv` prints `No known vulnerabilities found` with no `--ignore-vuln` added; gitleaks and the leak gate untouched. Functions under 60 lines, complexity under 7 (`ruff` `mccabe.max-complexity = 6` already enforces it).
- **Data rule and language (section 9).** English. Test fixtures use synthetic identities only (`sub` like `fake-sub-0001`, emails at `example.com`); no real person's name or address in any test, doc or PR body.

## Do not

- Do not use Gradio's `auth_dependency` or `auth=` to protect `/ui`; both turn signed-out visitors away, and option (b) keeps them in.
- Do not read `GOOGLE_*`, `SESSION_SECRET` or any setting in `src/receipts/ui/**`, at import, or inside `create_app()`.
- Do not skip the ID token's signature check "because it came over TLS" without recording that choice and its reason in ADR-0008; the default is to verify against Google's published keys inside the real provider.
- Do not weaken `validate_claims` to accept any issuer or a missing `nonce`, and do not accept a `state` that is merely present rather than equal.
- Do not treat a correct passcode as a signed-in user, and do not count signed-in runs against the signed-out cap or the reverse.
- Do not store anything from the Google profile beyond `sub` and `email`; do not put the email or the Google token in the cookie or any log line.
- Do not edit `src/receipts/contracts.py`, `src/receipts/fakes/**` or `tests/conftest.py`; the fake identity provider lives in `src/receipts/auth/fake.py` and is injected explicitly.
- Do not add a second dependency, a `--ignore-vuln` flag, a `# type: ignore`, a pyright mode change, or a skipped test to get to green; on the third failed repair, stop and escalate with the trace.
- Do not write the new tests after the code, and do not call a test file green without having recorded it red first.
- Do not change the `X-Demo-Passcode` behaviour of `POST /api/runs`, the `/healthz` body or header, or `scripts/seed_demo_runs.py`.
- Do not fix the records with a footnote: the spec's non-goal line, the section 9 Data bullet and the issue's "retired for the UI" line are edited where they stand, not annotated below.
- Do not commit a `.env` file, a real email address, or a value from `~/.zshenv`; names only, everywhere.

- The session lasts 7 days; the OAuth round-trip cookie 10 minutes. Both are constants in `src/receipts/auth/session.py`, not settings.
- `GET /auth/me` is added as a small JSON route (401 or `{"email": ...}`) because it gives the UI, the tests and the reviewer one way to see sign-in state; it is not in the issue.
- Battlecards stay readable by id for everyone (`GET /api/runs/{run_id}`); the issue scopes History (the list), not the cards, and the voice agent reads cards through this route.
- Demo mode (no live settings) stays unauthenticated and uncounted: the demo replay costs nothing and writes nothing.
- The `runs.user_id` column reaches the deployed Neon table through an idempotent `ADD COLUMN IF NOT EXISTS` executed by `create_schema` (so the first live request after deploy performs it), unless ADR-0008 records a different step the owner runs by hand.
