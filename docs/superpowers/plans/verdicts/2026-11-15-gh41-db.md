**Is the drift test real evidence?** Yes, for the gap it names.
- `test_users_unique_on_neon_matches_the_mapping` (`tests/test_db_constraints.py:188-196`) reads Neon's unique constraints through `inspect(engine).get_unique_constraints("users")`. On Postgres, that call queries `pg_constraint` for `contype = 'u'`.
- It compares them with the mapping's `column.unique` set and pins both to `{"sub"}`.
- It is a catalogue check, not behaviour. The behaviour is proven by the duplicate-sub rejection, which went red on a fresh Postgres under sabotage d.
- What the drift test adds is the one thing the rejection cannot see on Neon: the mapping drifting away from a table that `create_all` will never touch again. It went red on Neon under sabotage d (1 of 12).
- Limit: it compares flattened column-name sets. A unique index created outside `pg_constraint` would not be seen. That does not apply here (`users_sub_key` is a constraint).
