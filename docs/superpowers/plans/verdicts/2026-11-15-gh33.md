| # | Severity | Finding | Citation (`file:line` or command + exit) | Fix |

| 1 | HIGH | The exact-path number check is a set test against the **whole page**, not a check that the match does not cut a number. A quote that ends inside `$199` still counts as `quote_exact` whenever `$19` also appears elsewhere on the page, and a pricing page that lists a $19 monthly and a $199 yearly price is a common layout. Page `Pro yearly: $199. Pro monthly: $19.`, quote `Pro yearly: $19`, claim `Pro yearly is $19.` gives `verified=True, quote_exact, None`, so the wrong yearly price shows as verified. The module docstring says "a substring that cuts a page number, such as `basic is $19` inside `basic is $199`, is not `quote_exact`", and the PR body says "a quote "$19" no longer exact-matches inside a page's "$199"". Both are false for this input. This is not a regression (main gives the same result), but the stated fix is incomplete. No test puts the cut-off token elsewhere on the page. | `src/receipts/verify/rules.py:161`; docstring `rules.py:21-23` and `:157-159`; tests `tests/test_verify.py:234` (every page there holds only the cut number); probe `scratchpad/scripts/probe.py` case `cut-199-with-19-elsewhere`, exit 0 on head and on main | Check the boundary at the match position. For example, accept an exact hit only when no occurrence of `quote` in `body` is followed by `\d`, `[.,]\d` or `%` (when the quote ends in a digit), and none is preceded by `\d` or a currency sign (when the quote starts with a digit). Alternatively, compare the number tokens of the body slice widened to token boundaries. Add a test with `$199` and a separate `$19` on the same page.
